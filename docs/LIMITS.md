# 限制与配置

## 1. 限制总表

| 项目 | 限制 | 说明 |
| --- | ---: | --- |

| multipart 文件合计 | 160MB | 只统计启用的文件字段 |

| 单次请求逻辑输入 | 256MB | 包含 Body、Base64、Headers、URL 等估算 |
| 单响应保留 | 32MB | 超出后截断并标记 |
| 历史响应原文 | 512KB | 仅不超过该值的响应可参与差异对比 |
| 历史条数 | 10 | 本地 localStorage |
| 最大活动任务 | 32 | 单请求与批量合计 |
| 并发请求工作预算 | 768MB | 按 IPC 字节数 × 3 估算，非队列等待 |
| 并发响应工作预算 | 768MB | 单请求预留 96MB，批量预留 64MB，非队列等待 |
| 批量总请求数 | 1000 | 并发数 × 轮数 |

| 批量逻辑输入 | 64MB | 请求大小 × 总请求数 |

这些限制用于控制误操作、内存峰值和界面阻塞，不代表目标 API 的限制。

## 2. 文件上传配置

### 在哪里配置

Body 页签中选择 `form-data` 或 `binary` 后，在 Body 类型选择框右侧调整：

```text
单次上传上限(MB) [1]
```

### 配置规则

- 默认值：`1`。
- 最小值：`1`。
- 最大值：`128`。
- 步长：`1MB`。
- 非数字会恢复默认值；超出范围会夹到边界。
- 配置随草稿保存在应用本地。
- 降低配置不会删除已选文件，但发送前会按实际 Base64 解码大小重新检查。

### 超限提示

选择文件时提示：

```text
单个文件 2.0MB 超过上限 1.0MB；请在 Body 区调整“单次上传上限”后重试
```

### 为什么不是无限大

文件在发送过程中会经历：

1. WebView 读取文件；
2. Data URL / Base64 编码；
3. JSON 序列化；
4. Tauri IPC 传递；
5. Rust JSON 解析；
6. Base64 解码；
7. multipart 或 binary 请求体。

同一时刻可能存在多份副本。即使最终文件是 128MB，中间峰值也可能明显高于 128MB。默认 1MB 是为了避免普通测试中的误选和内存尖峰。

## 3. 请求与响应限制

### 请求

- 单次 IPC 字符串超过 256MB 会在 Rust 解析前拒绝。
- Rust 再次检查逻辑请求大小，包含 URL、方法、Headers、Params、Body 和文件 Base64。
- multipart 会先按输入估算，再按实际生成的 boundary、Header 和 Body 复核批量预算。
- 请求 URL 只支持 `http` 和 `https`。

### 响应

- 单请求最多读取并保留 32MB。
- 超过上限时停止继续读取响应体，返回已读取部分并设置 `truncated=true`。
- 批量单份样本最多保留 512KB；达到上限时停止读取并设置 `truncated=true`，不继续下载剩余 Body。
- 批量样本总预算 16MB，由所有并发响应共享；预算耗尽时对应请求也会停止读取。
- `sizeBytes` 统一表示实际保留的响应体字节数；`truncated=true` 时不能用于推算完整响应大小。
- 批量明细和样本均提供 `truncated`，表示因样本上限或共享预算停止读取；响应恰好等于上限时也可能为 `true`，界面统一显示“已达上限”。

## 4. 批量限制

批量以当前请求为模板，前置脚本与变量替换只执行一次。

```text
总请求数 = 每轮并发数 × 轮数 ≤ 1000
逻辑批量输入 = 编码后请求大小 × 总请求数 ≤ 64MB
```

示例：

- 10KB 请求、100 次：约 1MB 逻辑输入，可通过。
- 1MB 请求、100 次：约 100MB 逻辑输入，会被拒绝。
- 空 Body 的小请求可运行到 1000 次，但目标服务和网络仍可能成为瓶颈。

请求体在 Rust 中只准备一次，后续并发请求共享 `Bytes`，不会为每个并发请求重新解码文件或复制大 Body。

批量只保留第一份 2xx/3xx 响应作为样本；4xx/5xx 仍计入状态分布和失败数，但不作为样本。`durationMs` 是包含预处理和轮间隔的总墙钟耗时；`rps` 的分母只统计各轮请求执行时间，不含预处理和轮间隔。

## 5. 并发与内存

- 活动任务上限为 32。
- Rust 使用 768MB 的请求工作预算，按 IPC JSON 字节数 × 3 估算；另有 768MB 响应工作预算。
- 响应预算按 Body、Base64 和余量估算预留：单请求 96MB（32MB Body），批量 64MB（16MB 共享样本）。
- 预算不足时立即返回“并发请求内存预算不足”或“并发响应内存预算不足”，不会在应用内无限排队。
- 请求预算覆盖命令开始执行后的解析、编码和请求持有阶段；响应预算覆盖命令执行到结果返回前的响应持有阶段。
- Tauri IPC 在命令被调用前已接收的字符串、命令返回后的 IPC 序列化，以及 WebView 解码后的副本不受 Rust guard 直接约束；正常 UI 一次只发送一个任务，恶意或异常页面脚本仍可能制造额外峰值。

这是当前架构的残余风险，不是硬性的物理内存上限。固定响应预留会限制同时运行的大响应任务数量，小响应也可能因其他任务占用估算预算而被拒绝；它不是物理内存硬上限。

## 6. cURL 导入边界

- 只解析单条 `curl` 命令，不启动进程、不执行 Shell、不展开环境变量。
- 支持常用方法、URL、Header、文本 Body、Basic 认证、超时、重定向和 TLS 选项。
- `@file`、multipart、binary 文件、文件读写、证书文件、多 URL 和未知选项会明确拒绝，不会自动转换。
- 导入会替换当前请求；脚本和上传上限保留，运行中的请求不可导入。
- 文本解析在 WebView 主线程同步执行。1MB 输入、4096 参数与 4096 查询参数上限用于限制解析时间和内存峰值；未做低端设备性能实测。

修改解析器常量需要重新构建应用，上传上限仍可在 Body 区域直接调整。

## 7. 可配置项

| 配置 | 位置 | 默认值 |
| --- | --- | --- |
| 单次上传上限 | Body 页签 | 1MB |
| 请求超时 | 请求区选项栏 | 30000ms |
| 跟随重定向 | 请求区选项栏 | 开启 |
| 忽略证书 | 请求区选项栏 | 关闭 |
| 批量并发数 | 并发抽屉 | 10 |
| 批量轮数 | 并发抽屉 | 1 |
| 批量轮间隔 | 并发抽屉 | 1000ms |
| JSON 树默认展开深度 | 代码常量 | 2 |
| 活动任务上限 | `server/src/main.rs` | 32 |
| 响应工作预算 | `server/src/main.rs` | 768MB（单请求 96MB / 批量 64MB 预留） |
| IPC 输入上限 | `server/src/main.rs` | 256MB |
| 单请求大小上限 | `server/src/core.rs` | 256MB |
| 单响应上限 | `server/src/core.rs` | 32MB |
| 批量预算 | `server/src/core.rs` | 64MB 输入 / 16MB 样本 |

修改 Rust 或前端常量后需要重新构建应用。仅调整“单次上传上限”不需要重新构建。
